# 文档翻译 · macOS 原生版

SwiftUI 原生界面，内置 Python 文档引擎。当前交付面向本机 Apple Silicon Mac；应用声明最低 macOS 14，实际验证系统为这台 Mac 的 macOS 27.2。

快速开始请看 [简短使用说明](使用说明.md)。

## 使用

1. 打开 `~/Applications/DocTranslator.app`（本机已安装），或构建产物 `dist/DocTranslator.app`。应用自动启动本机引擎，无需启动终端、安装 Python 或输入额外的应用密码。
2. 打开右上角「API 设置」或按 `⌘,`，填写名称、Base URL、模型和 API Key；保存后点击「测试已保存配置」。接口需兼容 OpenAI Chat Completions。测试连接会发送一个很短的请求。修改字段后需要重新保存才能测试；切换配置、关闭设置或退出时会提示处理未保存的修改。
3. 按 `⌘O` 选择一份或多份 PDF、DOCX、PPTX、XLSX；也可拖入窗口，或在 Finder 中使用「打开方式 → 文档翻译」。文件逐个解析，底部显示队列进度；单个文件失败不会中断其他文件，可查看失败原因。「停止后续导入」仅移除尚未开始的项目，当前文件继续处理。单个文件上限为 100 MB。导入后选择配置和目标语言，再开始翻译。
4. 「段落对照」将原文和译文并排显示、共同滚动，并在翻译过程中逐批更新。完成或取消后可点击译文修订。草稿自动保存在本机，切换文档、切换视图和重启后保留；点击「保存到译文」或「保存全部草稿」后才更新导出文件。保存失败会保留草稿，「放弃修改」只清除对应草稿。
5. 「页面预览」支持适应宽度、缩放和翻页，输入页码后按回车可直接跳转，也可用首页、末页按钮和 `⌘←` / `⌘→` 翻页。尚未翻译时也能查看原文页面。PDF 直接预览；Office 文档的页面预览需要本机安装 LibreOffice。没有 LibreOffice 时仍可翻译、阅读段落和导出。
6. 点击「导出译文」，选择保存位置。存在草稿时，可选择保存全部后导出，或仅导出已保存版本并保留草稿。取消导出或取消保存位置选择时不会应用草稿；保存失败则停止导出。导出格式与原文件相同，文件面板限制为对应格式。
7. 点击「归档文档」整理历史记录。归档保留原文、译文、翻译进度和草稿；在侧栏状态中选择「已归档」可阅读、导出或恢复。翻译中需先取消并等待保存结束。

PDF 译文放不进原位置时，会保留该位置的原文并显示排版提示。「查看段落」或「排版待检查」筛选可定位这些段落；缩短译文并保存后，会重新检查版式。此类文档也会出现在「待处理」中。

侧栏可按文件名搜索，并筛选待翻译、翻译中、待处理或已完成的文档。「待处理」包括失败、取消，以及仍有未翻译段落的已结束任务。按 `⌘F` 搜索当前文档的原文、译文和草稿；也可仅查看未翻译段落或修订草稿。搜索不会修改文档或清除草稿。

关闭应用会停止尚未开始的导入；再次打开后可重新选择这些文件。已导入的文档、修订草稿和已保存的翻译进度会保留。

取消会等待当前批次结束。退出应用时会保存已完成批次；若服务仍未响应，应用会在有限等待后结束引擎。再次打开后使用「继续翻译」，会跳过已保存的完整段落。首次开始时会保存模型、服务地址、语言和批次参数；编辑 API 配置后，已有任务仍沿用原任务配置。API Key 仍从密钥存储读取，更新密钥可用于已有任务。需要换模型或目标语言时，请重新导入一份文档。0.1.0 及更早任务缺少模型快照，会在首次续翻时使用当时的配置建立快照。

选择模型或目标语言后默认值会立即保存，无需先开始翻译。

阅读视图、页码、缩放和段落位置按文档保存；重新打开应用时会回到上次阅读的文档，包括已归档文档。段落位置按段落恢复，不保留段落内的像素偏移；搜索和筛选不会覆盖正常阅读位置。阅读位置保存失败时底部会提示并提供重试。

## 数据和限制

- 数据、配置和日志位于 `~/Library/Application Support/DocTranslatorMac/`；更新或移动 `.app` 不会迁移或清除这些数据。桌面版不自动删除 30 天以前的任务。
- API Key 沿用项目的密钥存储，优先使用 macOS 钥匙串，无法使用时退回本机加密文件。应用和内置引擎通过仅本机可访问的随机端口及每次启动的随机凭据连接。
- 文档段落会发送到所配置的翻译服务。使用本机模型服务时可在本机完成翻译。
- 继承原引擎的格式限制：扫描 PDF 需要先做 OCR；复杂 PDF、公式和长译文可能出现排版问题；Word 段落内混合样式、PPT 图表/SmartArt、Excel 图表和图片的保真度有限。建议保留原文并检查导出结果。
- 本版本为本机签名的自用构建，未进行 Developer ID 公证或 App Store 分发。仅验证了当前 Apple Silicon Mac；其他系统版本与 Intel Mac 未验证。

## 开发与构建

仓库根目录运行：

```sh
bash macos/build_app.sh
```

构建需要 `uv` 和完整 Xcode。脚本优先使用 `DEVELOPER_DIR`，否则寻找 `/Applications/Xcode.app` 或 `Xcode-beta.app`，不会修改系统的全局开发工具选择。脚本创建 Python 3.12 环境、安装依赖、构建 SwiftUI 程序、冻结引擎、收集许可证并签名。

产物：`macos/dist/DocTranslator.app` 和 `macos/dist/DocTranslator-macOS-arm64.zip`。运行时不依赖仓库路径或虚拟环境。当前包包含代码、Python 运行时和依赖的许可证，见应用资源目录下 `LICENSE-doc-translator.txt`、`ThirdPartyNotices.txt`。

构建产物实际位于 `~/Library/Application Support/DocTranslatorBuilds/<项目路径摘要>/dist/`，`macos/dist` 指向该目录。这让源码留在同步目录中，同时保持应用包签名稳定。首次构建会保留并迁移已有 `dist` 内容。ZIP 与 `.app` 都包含完整运行时；拷贝 `.app` 本身即可独立运行。构建目录与应用的文档数据目录相互独立。
